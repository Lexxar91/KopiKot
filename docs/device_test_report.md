## Установка и запуск

Включить отладку по USB и разрешить подключение компьютера на телефоне.
Из корня проекта проверить устройство и установить текущий проверочный APK:

```bash
adb devices -l
sha256sum build/app/outputs/flutter-apk/app-debug.apk
adb -s DEVICE_ID install -r build/app/outputs/flutter-apk/app-debug.apk
```

Заменить `DEVICE_ID` идентификатором своего устройства. Команды здесь приведены
для ручного выполнения; установка ещё не выполнялась. При конфликте подписи
остановиться: не удалять приложение с чужим прогрессом. Для финальной приёмки
подставить release APK после настройки собственной подписи и имени пакета
по [инструкции сборки](setup_ubuntu.md).

## Методика времени и журнал дефектов

Измерять на физическом устройстве без подключения Flutter debug-сессии.
Указать, что считается стартом: нажатие иконки после принудительной остановки
до полностью готового первого экрана. Отдельно проверить первый запуск новой
установки и пять запусков с сохранённым профилем. Не выдавать это за холодный
старт после перезагрузки телефона, если перезагрузки не было.

Для подтверждения бюджета, покупки, перевода, задания и завершения периода
измерить от нажатия кнопки подтверждения до обновлённых данных и доступного
интерфейса. Сделать по пять повторов на сбрасываемых тестовых данных; записать
все значения и максимум, не только среднее. Использовать внешнюю видеозапись
с известной частотой кадров; если запись ведётся на самом телефоне, отметить
её возможное влияние. Зафиксировать также падения, зависания и потерю прогресса.

| Замер | Значения, секунды | Максимум | Итог |
| --- | --- | --- | --- |
| Первый запуск новой установки | Не измерено | — | Не выполнено |
| Пять запусков сохранённого профиля | Не измерено | — | Не выполнено |
| Подтверждение бюджета / покупка / перевод | Не измерено | — | Не выполнено |
| Ответ задания / завершение периода | Не измерено | — | Не выполнено |

Дефект записывать как: ID, сборка и устройство, исходное состояние, точные шаги,
ожидаемое/фактическое поведение, повторяемость, приложение с записью или журналом.
После исправления повторить исходный сценарий и соседние операции с балансом.
