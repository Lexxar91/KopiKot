КопиКот

Мобильная игра для детей 7–11 лет о финансовых решениях и заботе о виртуальном питомце. Ребёнок планирует игровые монеты, покупает товары, копит на цели и сравнивает план с результатом. Приложение работает локально на Android 8.0+.

Статус сдачи: подписанный release APK собран локально; проверка на

физическом устройстве, загрузка в Яндекс Диск и финальные материалы ещё впереди.

Package ID — com.lexxar91.kopikot, версия — 0.1.0+1.

Возможности

- Локальный профиль без регистрации, выбор окраса и аксессуара питомца.

- Бюджет по категориям «Нужное», «Радость», «Подарки» и «На мечту»; покупки доступны только при достаточном остатке кошелька.

- 21 товар, 3 цели накоплений, ветеринарный осмотр, история покупок и гардероб.

- 6 финансовых заданий по темам «Планирование», «Покупки» и «Сбережения». Первое завершение приносит 12 коткоинов, либо 11 при низкой сытости или энергии; повторное прохождение — тренировка без повторной награды.

- Котодерево с одним видом саженца: посадка стоит 20, зрелый сбор через 5 игровых дней приносит 50 коткоинов; ранний сбор даёт 30.

- Ежедневная награда от 10 до 20 коткоинов. В обычном режиме новый игровой день открывается по местной календарной дате; в деморежиме период можно завершить вручную.

- Шкалы сытости, энергии и радости уменьшаются со временем. Без осмотра 72 часа энергия начинает убывать вдвое быстрее.

- Прогресс питомца сохраняется между запусками. Взрослый раздел позволяет переключить тестовый профиль, сбросить его или удалить обычный профиль.

Flutter и Android на Ubuntu

Текущее состояние

Обновлено 17 сентября 2026 года. Пользователь установил зависимости; его вывод flutter doctor -v подтверждает Ubuntu 26.04.1 x86_64, Flutter stable 3.47.2, Dart 3.13.2, Android SDK / Build-Tools 36.0.0 и JDK 21.0.12. Лицензии Android приняты. Flutter использует /usr/lib/jvm/java-21-openjdk-amd64, независимо от общесистемной Java 25. Android-каркас создан, пакеты разрешены (pubspec.lock).

Сейчас для запуска из корня проекта достаточно flutter pub get, flutter devices, flutter run -d DEVICE_ID (ID Android-телефона/эмулятора). Разделы установки ниже нужны при подготовке нового окружения. Проверка dart analyze у пользователя прошла; flutter analyze ранее падал внутри LSP-канала. Причина падения не доказана; кириллица в пути была только гипотезой. Linux desktop toolchain не нужен для разработки Android-приложения на Ubuntu.

Первая APK-сборка дополнительно установила NDK 28.2.13676358 (версия из Flutter), платформу Android 35 и CMake 3.22.1. Для нового окружения их можно поставить так:

sdkmanager --sdk_root=/home/dmitriy/Android/Sdk "ndk;28.2.13676358" "platforms;android-35" "cmake;3.22.1"

Isar Android-модуль использует compileSdkVersion 35; SDK 36 при этом остаётся. Предупреждение Still waiting for package manifests означает ожидание сетевого каталога; успех установки подтверждается завершением команды, а не этим сообщением.

Это подготовка Android-приложения. Отдельно устанавливать Dart не нужно: он входит в Flutter SDK. Инструкции основаны на установке Flutter и настройке Android.

1. Системные пакеты

В терминале:

sudo apt update
sudo apt install git curl unzip xz-utils zip libglu1-mesa openjdk-21-jdk

Пакет openjdk-21-jdk доступен в подключённых репозиториях этой Ubuntu. Вместо установленной Java 25 для Flutter используем JDK 21: Java 25 требует Gradle 9.1 или новее, а Java 21 поддерживается с Gradle 8.5. Источник: матрица совместимости Gradle. Общесистемную Java переключать не нужно — ниже задаётся JDK только для Flutter.

2. Flutter SDK

Откройте официальный архив Flutter, выберите Linux → stable → x64 и скачайте архив .tar.xz. Для зависимостей проекта нужен Flutter с Dart 3.12 или новее.

Создайте каталог:

mkdir -p /home/dmitriy/development

Распакуйте скачанный архив в этот каталог через файловый менеджер. Результирующий путь должен быть /home/dmitriy/development/flutter/bin/flutter.

Откройте /home/dmitriy/.bashrc в редакторе и добавьте строку один раз:

export PATH="/home/dmitriy/development/flutter/bin:$PATH"

Затем в терминале:

source /home/dmitriy/.bashrc
flutter --version
dart --version
flutter config --jdk-dir=/usr/lib/jvm/java-21-openjdk-amd64

Первый запуск может загружать дополнительные файлы. Перезапустите IDE, чтобы она увидела новый PATH. Если IDE попросит путь к Flutter SDK, укажите /home/dmitriy/development/flutter.

3. Android SDK

Скачайте Linux-версию Android Studio и установите по официальной инструкции. Запустите мастер первоначальной настройки. Android Studio удобно использовать для SDK и эмулятора, а писать код можно в текущей IDE.

В More Actions → SDK Manager:

1. На вкладке SDK Platforms установите Android API 36.

2. На вкладке SDK Tools установите Android SDK Platform-Tools, Android SDK Command-line Tools (latest), Android SDK Build-Tools, NDK (Side by side) и CMake. Android Emulator нужен при запуске на эмуляторе.

3. Нажмите Apply и дождитесь завершения загрузок.

Если созданный Flutter-проект запросит другую версию SDK или NDK, установите именно её через SDK Manager: версии определяет установленный Flutter.

Укажите каталог SDK (ниже стандартный путь; проверьте его в SDK Manager):

flutter config --android-sdk=/home/dmitriy/Android/Sdk
flutter doctor --android-licenses
flutter doctor -v

Команда лицензий покажет условия — прочитайте их и подтвердите принятие в терминале. В flutter doctor важны успешные проверки Flutter и Android toolchain. Замечания о Chrome или Linux desktop не блокируют Android-сборку.

4. Инициализация проекта и зависимости

Исходники лежат в каталоге с пробелами и кириллицей. Если Android/Gradle выдаст ошибку пути, перенесите проект, например, в /home/dmitriy/development/KopiKot и откройте новое расположение в IDE.

В текущем расположении выполните:

cd '/home/dmitriy/Рабочий стол/KopiKot'
flutter pub get
dart format lib
dart analyze
flutter test

Android-обвязка уже есть в репозитории, повторять flutter create не нужно. Для этой сборки установлен com.lexxar91.kopikot; package ID зафиксирован в Android-обвязке и не должен меняться после передачи APK, иначе Android будет считать приложение другим.

В android/app/build.gradle.kts уже задан minSdk = 26 — это минимальный Android 8.0 по ТЗ. compileSdk и targetSdk не нужно понижать до 26: они отвечают за другие параметры сборки. Проверьте, что зависимости не требуют более нового минимального Android.

После настройки соберите проверочный APK:

dart run build_runner build

6. Релизная сборка для сдачи

ТЗ требует подписанный release APK, устанавливаемый без IDE. Для текущего состояния проекта APK уже собран; физическая установка и проверка игрового сценария ещё нужны. Полная инструкция подписи: Android release в Flutter.

1. В проекте установлен applicationId/namespace com.lexxar91.kopikot (по владельцу GitHub-репозитория). Если команда использует собственный домен, перед первой публикацией согласованно замените идентификатор и пакет MainActivity.

2. Release-keystore создан вне репозитория по пути /home/dmitriy/kopikot-release.jks. Не создавайте другой ключ для обновления этого приложения. Следующая команда приведена только для нового проекта/нового владельца приложения:

   keytool -genkeypair -v -keystore /home/dmitriy/kopikot-release.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias kopikot

3. Локальный android/key.properties уже настроен по образцу android/key.properties.example. Файл содержит путь storeFile, пароли и keyAlias=kopikot; он исключён из Git. Пароли не публикуйте. Защитите файлы:

   chmod 600 android/key.properties
   chmod 600 /home/dmitriy/kopikot-release.jks

Сохраните защищённую резервную копию ключа и паролей вне репозитория. Файл свойств и расширения .jks, .keystore, .p12 исключены из Git.

4. Настройка signingConfigs.release уже подключена. Release не использует debug-ключ: задача verifyReleaseSigning проверяет постоянный applicationId, наличие свойств и файла ключа, затем Android проверяет подпись. Debug-сборка не требует key.properties.

Предварительная проверка без сборки APK, из корня проекта:

   cd android
   JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ./gradlew app:verifyReleaseSigning
   cd ..

Проверка уже прошла в настроенном окружении. На другом компьютере она завершится ошибкой до размещения keystore и локального key.properties.

5. Проверьте версию в pubspec.yaml (сейчас 0.1.0+1) и выполните:

   flutter analyze
   flutter test
   flutter build apk --release

Тесты игры уже добавлены. Если flutter analyze снова падает внутри LSP, используйте dart analyze и отдельно сохраните сообщение о сбое инструмента.

Файл для установки: build/app/outputs/flutter-apk/app-release.apk. Перед сдачей проверьте подпись утилитой apksigner verify --verbose --print-certs из установленной версии Android SDK Build-Tools, передав ей путь к APK. Сверьте сертификат с собственным ключом, затем установите APK на физический телефон и пройдите сценарий проверки. Успешная сборка сама по себе не подтверждает сохранение прогресса, работу офлайн или все требования ТЗ.

В отчёте зафиксируйте flutter --version, dart --version, flutter doctor -v, версии Android SDK/Gradle, версию APK и результаты проверки устройства. Результаты выполненных проверок: verification.md. Релизная подпись и проверка на устройстве ещё не выполнены.

Реализованное хранение

ProfileRecord (схема 9, ID 1 — обычный, ID 2 — тестовый) хранит имя, внешность, гардероб, баланс, накопления, номер периода, состояние, источник/сумму стартового дохода, подтверждённый план, выбранную цель, остатки по целям, историю операций, попытки/результаты заданий и итоги периодов. Наборы хранятся вложенными записями Isar внутри профиля; для небольшого MVP это позволяет сохранять все последствия одним put в транзакции. Миграции схем 1–9 находятся в локальном хранилище; актуальную версию следует сверять с ProfileRecord.schemaVersion. LocalGameStore открывает finny.isar в каталоге поддержки приложения. LocalGameRepository преобразует запись в независимую от Isar domain-модель. GameController публикует результат после записи; ошибка не очищает форму.

Создание записывает 100 монет и источник «Подарок на знакомство» одной транзакцией. Повторное создание отклоняется. Бюджет проверяется и сохраняется в транзакции, остаток = баланс при подтверждении − нужно − хочется − подарки − на мечту. Отрицательные суммы и превышение баланса отклоняются; нулевые категории допустимы. Подтверждение не меняет баланс и накопления. Повторное подтверждение отклоняется. Текущий баланс не восстанавливается из стартовой суммы при перезапуске.

Справка читается из assets/content/help.json, покупки и цели — из catalog.json, шесть заданий — из tasks.json. Импорт неизменяемых определений в базу не нужен: они доступны офлайн в assets, а все изменяемые данные сохраняются в Isar. Каталог проверяет версию, уникальность ID, категории, цены и эффекты. Ссылочные ID нельзя удалять из обновлённого каталога без отдельной миграции сохранений. Для заданий проверяются типы, ссылки на товары, допустимость наград и выполнимость числовых условий. Миграции следующих версий добавляются вместе с соответствующими функциями. Неизвестная версия профиля вызывает ошибку, а не удаление сохранения. Android-резервное копирование отключено (allowBackup=false).

Профили и раздел взрослого

AppSettingsRecord — отдельная коллекция с записью ID 1 и признаком testProfile и reduceMotion. Отсутствие записи в старой базе означает обычный режим и отсутствие пользовательского ограничения движения. Чтение выбранного профиля согласовано транзакцией; все игровые команды работают с его ID. GameProfile.isTest выводится из ID записи и сохраняется при копировании.

Переключение режима и первое создание демопрофиля происходят в одной транзакции. Перед переключением запись проверяется: повреждение не меняет выбранный режим. Повторный вход продолжает игру; сброс заменяет только запись ID 2 исходным тестовым профилем. Его стартовый баланс сейчас расходится с ожиданием теста; подробность указана в карте контента. Удаление обычного профиля удаляет запись ID 1 со всеми вложенными данными, оставляя тестовый профиль. В тестовом режиме обычное удаление запрещено даже на уровне хранилища. Удаление и сброс не требуют сети.

AdultAccessButton доступен на знакомстве и главном экране. Каждый вход требует нового арифметического примера; это барьер от случайного действия, не проверка возраста. AdultScreen показывает цель обучения, пройденные темы и итоги без негативных оценок. Смена режима, сброс и удаление подтверждаются через общий GameActionDialog. Ошибка оставляет диалог для повтора; успешная операция возвращает к корню навигации, убирая формы предыдущего профиля. Подробности и ограничения удаления: локальные данные.

ReduceMotionController читает/сохраняет предпочтение через тот же контракт репозитория, отдельно от состояния игры. Транзакционное обновление настроек сохраняет и выбор профиля, и предпочтение движения, не перезаписывая соседнее поле. В MaterialApp оно объединяется с системным флагом. AccessiblePageTransitions и showAccessibleDialog применяют его к навигации, LoadingStatus — к загрузке. Состояние успеха публикуется после записи. Область проверки и UX-решения: доступность.

Покупки и накопления

В EconomyRules реализованы покупка, выбор цели, пополнение и снятие. Перед денежным действием требуется подтверждённый бюджет. Параметры товара берутся из каталога внутри репозитория: UI передаёт ID, но не назначает цену.

- Покупка: balance -= price; сытость/радость увеличиваются на эффект товара с верхней границей 100. Превышение плана разрешено, если хватает баланса, и сопровождается объяснением. Недостаток баланса запрещает покупку.

- Подарок учитывается отдельным видом покупки и сравнивается со своей строкой плана.

- Купленный аксессуар добавляется в гардероб. Надевание, смена и снятие не списывают монеты; владение и текущий вид сохраняются после перезапуска.

- Пополнение на x: balance -= x, savings += x, остаток выбранной цели += x. Сумма положительна и не превышает доступный баланс или остаток до стоимости цели.

- Снятие: обратный перевод только с выбранной цели, не больше её остатка. Диалог показывает новые суммы и удаление от цели до подтверждения.

- Общие накопления равны сумме остатков по целям. Смена выбранной цели не перемещает монеты. Несогласованная запись вызывает ошибку без потери данных.

- Факт расходов считается из истории текущего периода. Факт накоплений — пополнения минус снятия; он может быть отрицательным и подписан в UI.

- Каждая денежная команда имеет случайный ID, созданный один раз на диалог. Повтор того же ID с теми же параметрами не меняет данные; другие параметры с уже использованным ID отклоняются. Сохранённые ID переживают перезапуск.

Задания, периоды и рост

Правила заданий проверяют сценарии выбора из актуального tasks.json. Ошибочная попытка сохраняет объяснение, не отнимая монеты и прогресс. Правильное решение одновременно сохраняет завершение, награду и запись дохода. Повторная отправка завершённого задания, в том числе после перезапуска, не награждается. Учебные суммы отделены от настоящего игрового баланса.

PeriodRules закрывает игровой день при переходе местной календарной даты, сохраняет итог и выдаёт ежедневную награду по DailyRewardRules. Ручной переход доступен только в деморежиме. Повтор команды с номером уже завершённого периода ничего не меняет. Стадия роста вычисляется из итогов: в обычном режиме учитываются дни, выполнившие критерии нужд, плана и накоплений; в деморежиме — завершённые игровые дни. Вторая стадия открывается после двух, третья после четырёх подходящих дней. Неудачный день не отменяет достигнутую стадию. Точные условия и шесть учебных ситуаций: карта контента.

TasksScreen/TaskScreen показывают задания и формы, ProgressScreen — темы, стадию и сравнения каждого завершённого периода. На главном экране есть маршрут дня, активное задание, последнее начисление и быстрые действия. Внешность сохраняется на всех стадиях; выражения питомца зависят от состояния и действия.

Актуальные тесты находятся в каталоге test/ и меняются вместе с реализацией. Протокол физической Android-приёмки находится в `device_test_report.md` и пока не заполнен.

Его обновление не перезаписывает игровой прогресс. Загрузчик проверяет ID, ссылки, цены и поддерживаемые типы заданий. При невалидных данных показывает ошибку, не очищая базу.

Коллекции Isar находятся в data/local; domain-модели не содержат @collection. Денежные величины — целые игровые монеты (int), а не дробные double. Баланс и накопления — разные величины; будущая удалённая реализация должна сохранить те же контракты и инварианты.

Одна команда сохраняет все последствия в одной транзакции Isar. Например: проверка актуального остатка → списание → история → состояние питомца → фиксация. Повтор команды с тем же ID не выполняет операцию второй раз; выплата за завершённое задание и доход нового периода также защищены от повторного начисления. UI показывает успех после сохранения. Кнопка блокируется на время операции, но корректность обеспечивает и слой данных, включая повторный вызов.

Профиль и незавершённый период восстанавливаются при запуске. Удаление профиля удаляет связанные операции, цели и прогресс одной транзакцией, затем сбрасывает соответствующие провайдеры. Тестовый профиль имеет отдельный ID и сбрасывается к известному начальному состоянию, не затрагивая обычный профиль.

Игровой период и правила

Для MVP выбираем завершение периода кнопкой. Такой цикл позволяет пройти не менее пяти периодов подряд и в обычном, и в демонстрационном режиме. Доход не начисляется от повторного открытия экрана или перезапуска приложения.

Последовательность: начало и понятное начисление → редактирование плана → подтверждение → задания/покупки/накопления → итог план/факт → следующий период. Подтверждённый план неизменяем; доход от задания внутри периода показывается отдельно и не переписывает исходный план задним числом.

Обязательные инварианты:

- Все суммы неотрицательны. Сумма четырёх частей плана не превышает доступный бюджет; остаток равен бюджету минус сумма плана. Планирование само по себе не списывает монеты.

- Покупка проводится только после подтверждения и при достаточном балансе. Сначала видны цена, категория и ожидаемое влияние. При отказе база не меняется.

- Пополнение на x уменьшает баланс на x и увеличивает накопления на x. Снятие выполняет обратное изменение после отдельного подтверждения с показом результата.

- Покупки считаются в факте по категориям; пополнения и снятия показаны отдельно. Для оценки регулярности учитываем чистое пополнение за период, чтобы перевод туда-обратно не увеличивал учебный прогресс.

- Факт формируется из сохранённых операций периода, а не из текущих значений UI. Доходы имеют источник и сумму. Отрицательный остаток не допускается.

- Итог периода сохраняется один раз. Рост учитывает обеспечение нужд питомца, соответствие плану и регулярность накоплений за несколько периодов. Конкретные цены, награды и пороги роста задаются при балансировке, а не произвольно в UI.

- Радость — обратимое текущее состояние (в доменной модели поле mood); стадия развития — накопленный результат. Неудачное решение не уничтожает достигнутую стадию. Отказ от желаемой покупки не считается ошибкой. Дополнительное задание или новый план дают путь восстановления.

Расчёт срока накопления необязателен; в первой версии достаточно стоимости, накопленной суммы и остатка. Если срок появится, он должен опираться на понятное среднее регулярное пополнение и пересчитываться до подтверждения снятия.

Учебный контент и интерфейс

Нужно минимум по два задания на планирование, сбережения, платежи/покупки. Распределение монет, подбор корзины и пополнение цели — самостоятельные действия, а не шесть одинаковых тестов с вариантами ответа. Каждый исход получает объяснение. Новое задание существующего типа добавляется данными без переделки основной логики.

9 вариантов питомца получены сочетанием 3 окрасов и 3 аксессуаров; отдельно проверены 6 эмоций. Каталог содержит 13 покупок, включая обязательные, необязательные и подарки, 3 цели и 3 стадии роста.

Главный экран одновременно показывает питомца, баланс, накопления, цель, показатели состояния и активное задание. Проектируем под портретные 360 dp, кнопки от 48 dp, текст примерно от 16 sp и системное увеличение шрифта. Цвет сопровождается текстом/значком, звук и анимация отключаются. Подсказки доступны повторно. Раздел взрослого защищён арифметическим примером; сброс и удаление требуют отдельного подтверждения. Это защита от случайного действия, а не полноценная аутентификация.

Проверка и порядок разработки

1. Установить окружение, разрешить зависимости и собрать Android-каркас.

2. Реализовать профиль, создание питомца, Isar и восстановление после перезапуска.

3. Замкнуть один период: доход → план → покупки/задание/накопления → итог.

4. Добавить историю, рост, полный объём контента и пять демонстрационных периодов.

5. Добавить раздел взрослого, сброс/удаление, справку и настройки доступности.

6. Проверить сценарий из Приложения А, физическое устройство и релизную подпись.

Критичные автоматические проверки: перепланирование и перерасход; неизменность подтверждённого плана; покупка при нехватке; атомарность и повторные команды; пополнение/снятие; однократная награда; рост по серии периодов; перезапуск Isar; сброс только тестового профиля; проверка целостности контента. Проверка на физическом Android 8.0+ с ОЗУ от 3 ГБ обязательна отдельно: старт ≤5 секунд, визуальная реакция ≤1 секунды, работа офлайн и сохранение прогресса.

Игровые периоды и рост

Игровой день — местная календарная дата; в деморежиме переход можно выполнить вручную. Награды, бюджет, операции, закрытие дня и стадии роста регулируются корневым AGENTS.md и реализацией lib/domain/rules/. Для стадии развития учитываются сохранённые итоги, а не простое число нажатий; точные условия роста следует сверять с PeriodRules, чтобы не смешивать их с прежней моделью.

Интерфейс и доступность MVP

Принятые решения

Главный экран показывает питомца, доступный баланс отдельно от накоплений, состояние, выбранную цель, активное задание и объяснение последнего действия. Ребёнок сначала подтверждает бюджет, затем выбирает покупки, накопления или задание. Итог сравнивает план с фактом и предлагает следующий шаг. Отказ от желаемой покупки не оценивается как ошибка.

Экранные тексты и параметры ситуаций краткие; справка доступна повторно. Ошибки сопровождаются словами, не только цветом. У денежных действий есть отдельный диалог с суммой, последствиями и отменой; сброс и удаление находятся за барьером взрослого. Общий GameActionDialog сохраняет возможность повтора после ошибки записи, не закрывая форму с ложным сообщением об успехе.

Основной текст и подписи основных кнопок — 16 sp. Заголовки крупнее; небольшие вспомогательные подписи используют стандартную Material-типографику. Системное увеличение текста не ограничивается. Содержимое длинных экранов прокручивается, группы кнопок и вариантов внешности переносятся. Вспомогательные подписи и ошибки полей допускают до трёх строк. Диалог бюджета также прокручивается.

Для основных кнопок задана минимальная область 48 × 48 dp, для заполненных — 48 × 52 dp. Иконки справки и взрослого раздела имеют текстовые подсказки. Вектор питомца имеет семантическое описание окраса и аксессуара. Название стадии, сытость, энергия и радость дополнительно представлены обычным текстом.

Уменьшение движения

«Для взрослого» → «Отключить анимации переходов». Настройка общая для устройства и сохраняется в Isar независимо от выбранного профиля. Смена/сброс профиля и удаление обычной игры её не сбрасывают. При ошибке записи настройка не считается сохранённой; показано предложение повторить.

Системное disableAnimations также учитывается: итоговое значение — логическое ИЛИ системного и сохранённого предпочтений. Оно применяется к переходам страниц, открытию/закрытию всех диалогов и индикаторам загрузки. При отключении индикатор заменяется статичным текстом; смена темы не анимируется. Сам питомец статичен. Звуков в MVP нет. Стандартные реакции элементов Material и системной клавиатуры не являются игровыми анимациями; поведение на Android следует проверить отдельно.

Что проверено автоматически

UI-проверки находятся в test/current_ui_test.dart и связанных файлах; их текущие размеры/сценарии необходимо сверить с кодом теста перед повторным запуском. Действия взрослого

На экране знакомства или главном экране нажать замок «Для взрослого» и решить арифметический пример. Это защита от случайного входа, а не пароль или надёжная проверка возраста. В разделе видны назначение приложения, прогресс по темам, накопления и переход к итогам.

- «Открыть тестовый профиль» — первое создание или продолжение независимой игры. Обычный профиль не изменяется; режим сохраняется после перезапуска.

- «Вернуться в обычный профиль» — продолжение обычной игры или знакомство, если обычный питомец ещё не создан.

- «Сбросить тестовый профиль» — после подтверждения удаляется его прежний прогресс и создаётся исходный тестовый профиль. Стартовый баланс сейчас расходится с ожиданием теста; см. карту контента. Обычные данные не затрагиваются.

- «Удалить обычный профиль» — доступно в обычном режиме после подтверждения; удаляются питомец и все связанные операции, задания, цели и итоги. Открывается знакомство. Тестовое сохранение не затрагивается.

Отмена не изменяет данные. После успешного сброса или удаления отменить действие нельзя: облачного восстановления нет. Изменения выполняются транзакционно. Логическое удаление из Isar не является гарантированным физическим стиранием остаточных байтов с накопителя; такой гарантии приложение не даёт.

Сценарий демонстрации «Питомец Финни»

Этот документ — план показа, а не протокол проведённой приёмки. Сценарий с заранее заданными балансами заблокирован расхождением деморежима: инициализация профиля задаёт 9 990 коткоинов, новый игровой день начисляет ещё 10, но test/demo_repository_test.dart ожидает 1 000. До исправления и повторной проверки не использовать заранее рассчитанные суммы.

Перед демонстрацией

1. Собрать отдельный release APK с настроенной подписью. Текущая сборка — debug; статус и способ скачивания указаны в корневом README.

2. Использовать отдельное устройство или тестовый профиль. Не сбрасывать обычный игровой прогресс.

3. Устранить расхождение демобаланса, выполнить автоматические проверки и пройти протокол физического Android.

4. Подготовить игровой день с известным остатком, планом и журналом операций; перед записью зафиксировать реальные значения.

Черновик карточки RuStore

Это локальный комплект для конкурсной сдачи. В RuStore ничего не загружено и не опубликовано; аккаунт разработчика и финальная подпись не настроены.

Основные поля

Название: Питомец Финни.

Тип: Игра. Основная категория: Детские, без дополнительной категории. Это рабочий выбор для обучающей игры о питомце, а не банковского приложения. Такой профиль соответствует описанию категории в официальном перечне RuStore.

Целевая аудитория: дети 7–11 лет, при необходимости вместе со взрослым.

Краткое описание:

Заботься о Финни, планируй расходы и копи игровые монеты на мечту.

Полное описание:

Питомец Финни — спокойная обучающая игра о выборе и заботе. Создай своего

кота, придумай ему имя и выбери окрас и аксессуар.

Игровых монет не всегда хватает на всё сразу. Составь план: что нужно питомцу,

что хочется купить и сколько можно отложить на мечту. Выбирай еду, уход

и игрушки, сравнивай план с фактическими тратами и наблюдай за состоянием друга.

В шести заданиях по трём темам можно распределять бюджет, собирать корзину

и выбирать сумму накоплений. За первое верное решение начисляется награда.

Если решение не подошло, подсказка поможет попробовать ещё раз — заработанный

прогресс не исчезнет.

На пути к трём целям накопления хранятся отдельно от доступных монет. Питомец

проходит три стадии развития благодаря решениям за несколько игровых периодов.

Следующий период можно начать без ожидания реального времени.

Игра работает локально, без регистрации. Реальных платежей, рекламы и подписок

нет. Профиль сохраняется на устройстве. Во взрослом разделе доступны учебный

прогресс, отдельная тестовая игра, сброс, удаление обычного профиля и отключение

анимаций переходов. Звуки не используются.

Воспроизведение

Из корня проекта на подготовленном Linux x64:

flutter test tool/export_store_assets.dart --reporter expanded
flutter test test/store_assets_test.dart

Экспорт перезаписывает только перечисленные PNG в docs/store/ и ресурсы иконки в android/app/src/main/res/mipmap-*. Он использует временную Isar-базу, не пользовательские сохранения. Начальный профиль проходит пять периодов с покупкой каши и пополнением цели по 20 монет, затем одно задание и в шестом периоде ещё покупку каши/пополнение на 10: баланс 350, накопления 110, период 6, стадия «Опытный друг». В кадре задания выбраны каша и вода (35 из 40 учебных монет), но ответ ещё не отправлен. Данные экранов берутся из сохранённого снимка; рендер использует обычные тени Material, не отладочные обводки widget-теста.

Исходники: tool/artwork/finny_icon.dart, tool/export_store_assets.dart и lib/presentation/widgets/pet_portrait.dart. Шрифты берутся из установленного Flutter SDK. Происхождение и ограничения лицензий: реестр графики.
