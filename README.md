# KopiKot

MVP мобильного приложения для обучения детей финансовой грамотности через заботу о виртуальном питомце.

Основа — ТЗ **«Питомец Финни»**, аудитория 7–11 лет, Android 8.0+.
Локальная копия исходного ТЗ хранится в `docs/specification.txt` и не публикуется.

## Подготовка и запуск

Инструкция: [Flutter и Android на Ubuntu](docs/setup_ubuntu.md).

Реализованы создание питомца (9 вариантов внешности), гостевой профиль,
стартовые 100 монет с объяснением, современный главный экран, справка и бюджет
по четырём направлениям: нужное, желаемое, подарки и накопления.
Добавлены 13 покупок, 3 цели, пополнение/подтверждённое снятие и история покупок.
Аксессуары покупаются один раз, сохраняются в гардеробе, надеваются и снимаются
бесплатно. У питомца шесть объяснимых эмоций, зависящих от состояния и решений.
Есть 6 заданий по 3 темам, однократные награды, ручное завершение периодов,
итоги план/факт и 3 стадии роста. Профиль, операции, задания и итоги сохраняются
в Isar. Пять периодов с повторным открытием базы проверены автоматически.
Добавлены раздел взрослого с арифметическим барьером, отдельный тестовый
профиль со сбросом и подтверждаемое удаление обычного профиля.
Добавлено отключение анимаций переходов с сохранением настройки и учётом
системного предпочтения. Компоновка, контраст и нажатия проверены автотестами
на 360 dp при масштабе текста 1 и 2 в описанных состояниях.
Проверка на телефоне и финальные конкурсные материалы ещё впереди.
Собственная иконка уже подключена в Android; подготовлен
[черновик RuStore с четырьмя кадрами интерфейса](docs/store/listing.md).
Проверочная сборка: `build/app/outputs/flutter-apk/app-debug.apk`.
Release теперь требует отдельного ключа и постоянного имени пакета;
шаблонная подпись release через debug-ключ отключена. Образец настроек:
`android/key.properties.example`, порядок подготовки — в инструкции Ubuntu.

При установленном Flutter и Android SDK:

```bash
flutter pub get
dart run build_runner build
dart analyze
flutter test
flutter devices
flutter run -d DEVICE_ID
```

В последней команде замените `DEVICE_ID` идентификатором Android-телефона
или запущенного эмулятора. Android-каркас уже создан, повторять `flutter create` не нужно.
В текущем окружении `flutter analyze` ранее аварийно завершался внутри LSP;
для анализа используется `dart analyze`. Тесты реального хранилища сейчас настроены
на Linux x64 и используют ядро установленного пакета Isar без скачивания из сети.

## Структура исходного кода

```text
lib/
├── main.dart                         # Точка входа, ProviderScope и корневой виджет
├── presentation/
│   ├── screens/                      # Экраны
│   ├── widgets/                      # Переиспользуемые UI-компоненты
│   └── providers/                    # Riverpod-провайдеры и контроллеры UI
├── domain/
│   ├── models/                       # Модели предметной области
│   ├── rules/                        # Бюджет, покупки, накопления, итоги и рост
│   └── repositories/                 # Контракты репозиториев
└── data/
    ├── content/                      # Загрузка и проверка учебного контента
    ├── local/                        # Isar-источники данных
    ├── remote/                       # Будущие HTTP-источники данных
    └── repositories/                 # Реализации контрактов из domain

test/                                 # Тесты бизнес-правил, репозиториев и UI
assets/content/                       # Неизменяемый контент, читаемый из assets
docs/                                 # ТЗ, архитектура, требования и установка
```

Папка `data/repositories` добавлена намеренно: здесь живут конкретные реализации
контрактов, а `data/local` отвечает только за доступ к Isar. Это сохраняет цепочку
зависимостей: `UI → provider/controller → repository contract → implementation → data source`.

На старте не нужны отдельные `core`, `services`, `utils`, `features` или `remote`-классы.
Их стоит добавлять только при появлении конкретной задачи, чтобы MVP оставался простым.

## Локальное хранение

Все сохраняемые данные MVP должны проходить через репозитории в `isar_community`.
Коллекции с аннотацией `@collection` и сгенерированные схемы размещаются в
`lib/data/local/`; модели в `lib/domain/models/` не импортируют Isar или Flutter.
Преобразование между моделями хранения и предметной области выполняется в data-слое.
Riverpod связывает UI с контрактами репозиториев.

`data/remote/` внутри `lib/` зарезервирована для будущего API. Серверные зависимости
не требуются. Модели и правила по ТЗ описаны в [архитектуре](docs/architecture.md).

В `pubspec.yaml` предусмотрены Riverpod, Isar Community (API, нативная библиотека
и генератор), `path_provider` для каталога базы и `build_runner` для генерации.
Все три пакета Isar зафиксированы на одной версии по
[инструкции Isar Community](https://pub.dev/packages/isar_community).
Зависимости разрешены, `pubspec.lock` создан и должен храниться в Git.
Генератор Isar сообщил о более новой версии языка SDK (3.13) относительно своей
версии analyzer (3.12); генерация схемы прошла. Не добавляйте `dependency_overrides`
для подавления предупреждения — обновление требует отдельной проверки совместимости.
